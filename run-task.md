# ТЗ: Бэкенд «Сдача лабораторных работ» (лабораторная №3, ветка lab3-api)

## Контекст

В репозитории `asiigments-submit-application` находится Angular-клиент
системы «Сдача лабораторных работ» (`src/client`). Сейчас клиент работает
на браузерном мок-слое `src/client/app/mock` (mock-api-client, mock-db,
handlers по доменам: auth, profile, groups, labs, students, submissions,
seed, rate-limiter).

Контракт API и общие требования описаны в `docs/system-specification.md`
(читать обязательно) и `src/api/README.md`. Доменные модели клиента —
`src/client/app/shared/models.ts`; поведение эндпойнтов можно сверять с
обработчиками мок-слоя `src/client/app/mock/**/handlers.ts`.

## Задача

1. Создать серверную часть в `src/api` — монолитное приложение на
   **ASP.NET Core, .NET 8** (указание стека .NET 8 приоритетнее упоминания
   .NET 10 в README), обслуживающее REST API `/api/v1` и раздающее
   статику собранного Angular-клиента (SPA fallback: не-`/api` маршруты
   отдают `index.html`).
2. **Работу с БД замокать заглушками**: вместо EF Core + PostgreSQL —
   in-memory хранилище/репозитории-заглушки за интерфейсами, чтобы в
   следующей итерации подставить реальную БД без изменения контроллеров.
   Не тащить EF Core/PostgreSQL в эту итерацию.
3. **Убрать заглушки из фронтенда**: клиент должен ходить на реальные
   HTTP-эндпойнты бэкенда вместо `src/client/app/mock`. Слой
   `src/client/app/mock` удалить (или исключить из сборки), сервисы в
   `src/client/app/core/services` переключить на `HttpClient` с базовым
   URL `/api/v1`. Обновить конфигурацию Angular (proxy для dev-режима
   `/api` → Kestrel), unit-тесты клиента, которые использовали мок-слой.
4. Аутентификация: JWT в httpOnly-cookie (access 15 мин + refresh 7 дней)
   — по спецификации; на заглушках допустим упрощённый выпуск токенов,
   но эндпойнты и контракт должны соответствовать спецификации.
5. Health-check `GET /health`; Swagger UI только в dev.

## Требования к результату

- `dotnet build` собирается без предупреждений; unit-тесты бэкенда
  (`dotnet test`) проходят — покрывают как минимум бизнес-логику сервисов
  и контроллеры на заглушках.
- `ng build` клиента собирается; `ng test` проходит после удаления моков.
- Соответствие контракта `/api/v1` спецификации и текущим моделям клиента.
- README в `src/api` обновить: как запустить бэкенд, как настроен прокси.
