# Спецификация системы «Сдача лабораторных работ»

Версия: 1.1 · Дата: 2026-09-26
Основание: [docs/user-stories.md](user-stories.md) (v1.1), макеты [Figma «Сдача лабораторных»](https://www.figma.com/design/boOY0AZqW8bli9kIs8irws/Sdacha-laboratornyh)

Изменения в 1.1: добавлены регистрация (роль по умолчанию — студент), разделы «Группы» и «Доступ», редактирование профиля; семестр — номер семестра курса (1…N, не ограничен двумя); ведомость преподавателя строится по группе; API версионирован префиксом `/api/v1`.

---

## 1. Общие сведения

**Назначение.** Веб-система учёта сдачи лабораторных работ: студенты регистрируются и смотрят свои результаты, преподаватель ведёт список лабораторных, формирует группы, выдаёт студентам доступ к сдаче (включением в группу) и проставляет даты сдачи/защиты.

**Тип приложения.** Монолит: одно серверное приложение (ASP.NET Core) обслуживает и REST API, и статику собранного Angular-приложения (SPA). Одна БД PostgreSQL.

**Роли.** `teacher` (преподаватель), `student` (студент). Регистрация создаёт только студента; учётные записи преподавателей создаёт сид/администратор БД. Права разграничиваются на сервере и в маршрутах SPA.

**Ключевое понятие.** *Семестр* — порядковый номер семестра курса (1…N, `Labs__MaxSemester`, по умолчанию 10), а не семестр учебного года. Лабораторные и ведомости группируются по этому номеру.

**Вне области текущей версии:** подтверждение email при регистрации, массовый импорт пользователей, восстановление удалённых групп/данных, интеграционные API, мобильные макеты разделов преподавателя.

## 2. Стек и архитектура

| Слой | Технология |
|---|---|
| Клиент | Angular 20+ (standalone-компоненты, TypeScript strict, SCSS, Angular Material) |
| Сервер | .NET 10, ASP.NET Core (minimal APIs / controllers), EF Core 10 |
| БД | PostgreSQL 16+, Npgsql, code-first миграции EF Core |
| Аутентификация | JWT в httpOnly-cookie: access (15 мин) + refresh (7 дней) |
| Почта | SMTP через абстракцию `IEmailSender` (в dev — запись в лог) |
| Логирование | Serilog (файл + консоль), health-check `GET /health` |

```
┌─────────────────────────────────────────────┐
│              ASP.NET Core 10 (Kestrel)      │
│  /              → статика Angular (wwwroot) │
│  /api/v1/...    → REST API (версия в пути)  │
│  /health        → health check              │
└──────────────┬──────────────────────────────┘
               │ EF Core 10 (Npgsql)
        ┌──────┴──────┐
        │ PostgreSQL  │
        └─────────────┘
```

- **Версионирование API** — в пути: `/api/v1/...`. При несовместимых изменениях добавляется `/api/v2`, v1 поддерживается в переходный период. Клиент зашивает базовый префикс в один interceptor/конфиг.
- SPA fallback: все не-`/api` маршруты отдают `index.html` (deep-link и refresh работают).
- Dev-режим: Angular dev-server с прокси `/api` на Kestrel; Swagger UI только в dev.
- Развёртывание: один процесс приложения + PostgreSQL (docker-compose либо Kestrel за reverse-proxy). Конфигурация через переменные окружения (см. §10).

## 4. Функциональные требования

### 4.1. Регистрация и аутентификация (US-15, US-1)

**Регистрация** — `POST /api/v1/auth/register`:

- Поля: ФИО, логин, email, пароль, повтор пароля. Роль создаваемой учётной записи — всегда `student` (игнорируется/отсутствует во входных данных).
- Уникальность логина и email — проверка с понятными сообщениями («Пользователь с таким логином уже существует»).
- К паролю — требования из §8. Успех → 201, автоматический вход (ставятся cookie) и редирект на сдачи студента.
- Подтверждение email не предусмотрено (email используется только для восстановления пароля) — зафиксировано решение для v1.
- Анти-спам: не более 5 регистраций в час с одного IP.

**Вход** — `POST /api/v1/auth/login` с `{login, password}`:

- При успехе сервер ставит httpOnly-cookie и возвращает `{role, fullName}`.
- Ошибка любых неправильных данных — единое сообщение **«Неверный логин или пароль»** (не раскрывать существование аккаунта).
- Ограничение частоты: не более 5 попыток в минуту на пару (логин, IP) → 429.
- Экраны: десктопная и мобильная вёрстки; на десктопе ошибка — закрываемый баннер, на мобильном — текст под полями.
- Выход: `POST /api/v1/auth/logout` — отзыв refresh-токена, очистка cookie.

### 4.2. Восстановление пароля (US-2–4)

Поток: «Я забыл пароль» → email → код из письма → новый пароль.

1. `POST /api/v1/auth/recovery/request {email}` — всегда отвечает 200 (независимо от существования email). Генерирует 6-значный код, хранит **хэш** кода, отправляет на почту. TTL кода — 10 минут, одноразовый. Не более 3 запросов в час на email.
2. `POST /api/v1/auth/recovery/confirm {email, code}` — при совпадении возвращает краткоживущий `resetToken` (JWT, TTL 15 минут, назначение `password_reset`). Неверный код → **«Код восстановления не подходит»**; не более 5 попыток на код. На экране — ссылка «Переотправить код».
3. `POST /api/v1/auth/reset-password {resetToken, password, confirmPassword}` — меняет пароль, отзывает все refresh-токены пользователя, редирект на `/login`.

Экран «Смена пароля» (шаг 3): поля «Новый пароль», «Повторите пароль»; требования пароля выведены на экран и проверяются на сервере (§8). Десктопная и мобильная вёрстки.

### 4.3. Лабораторные работы — преподаватель (US-5–9)

Список (вкладка «Работы»), `GET /api/v1/labs`:

- Колонки: **Номер**, **Содержание**, **Семестр** (номер семестра курса), **Задание** (ссылка на репозиторий с заданиями), **Нужна защита** (чекбокс, read-only в списке), действия: ✏️ редактировать, 🗑 удалить.
- Пагинация: `page`, `pageSize=10`; ответ содержит `total` и подпись «Показать записи с X по Y из Z».
- Сортировка/фильтр: `?semester=N` и сортировка по семестру и номеру (иконка у колонки «Семестр»).
- Кнопка «+ Добавить…».

Создание/редактирование — `POST /api/v1/labs`, `PUT /api/v1/labs/{id}`. Форма «Новая работа»:

- Поля: **Номер** (целое > 0), **Семестр** (выпадающий список 1…`Labs__MaxSemester`), **Содержание работы** (строка до 500 символов), **Ссылка на задание** (опционально; добавляется/меняется кнопкой-«цепочкой» с тултипом «Нажмите на эту кнопку чтобы добавить или изменить ссылку»), чекбокс **Нужна защита**.
- Уникальность номера в пределах семестра → иначе 409 и сообщение об ошибке.
- Кнопки «Сохранить» и «Назад»; при ошибках валидации — баннер **«Данные заполнены неверно»** + подсветка полей.

Удаление — `DELETE /api/v1/labs/{id}`: диалог подтверждения **«Вы точно хотите удалить лабораторную №N в семестре №M?»** с «Yes»/«No»; на время диалога список заблокирован. Удаление каскадно убирает записи ведомости по этой работе.

### 4.4. Ведомость сдач (US-10, US-11)

Колонки ведомости = лабораторные выбранного семестра (упорядочены по номеру). Доступ к сдаче = членство студента в группе (§4.6).

**Преподаватель** (вкладка «Сдача работ»), `GET /api/v1/submissions?groupId=&semester=&page=&pageSize=5`:

- Селекторы: **группа** (обязательный, по умолчанию первая) и **семестр**; таблица — «ФИО × Лабы» студентов выбранной группы, у каждой работы колонки **Сдача** и **Защита** (даты либо пусто).
- Даты проставляются date-picker'ом прямо в ячейке (`ru`-локаль); `PUT /api/v1/submissions` с `{studentId, labId, submitDate?, defenseDate?}` — частичное обновление, пусто = сброс.
- Запоминается `updated_by` (кто менял) и время изменения.
- Пагинация по студентам группы: 5 на страницу, «Показать записи с X по Y из Z», номера страниц и стрелки.

**Студент**, `GET /api/v1/me/submissions?semester=`:

- Видит **только свою строку**: колонки «Лаб 1–N» с парами «Сдача»/«Защита», режим чтения (редактирование недоступно, данные чужих студентов не отдаются).
- **Выбор семестра** — выпадающий список семестров, в которых есть лабораторные (`GET /api/v1/semesters`); при переключении таблица перезагружается.
- Ответ содержит признак `hasGroup`: если студент не включён в группу — вместо таблицы предупреждение «Вы не включены в группу, доступ к сдаче лабораторных не выдан».
- Обязательны **две вёрстки**: полноэкранная (десктоп) и мобильная.

### 4.5. Группы (US-16) — преподаватель

Раздел «Группы»:

- Список групп: название, количество студентов; создание, переименование, удаление. `GET/POST/PUT/DELETE /api/v1/groups`.
- Удаление группы — с подтверждением («Вы точно хотите удалить группу N?»); студенты группы **не удаляются**, у них сбрасывается `group_id` — они теряют доступ к сдаче.
- Карточка группы — состав: `GET /api/v1/groups/{id}/students` (ФИО, логин, email, пагинация), действие «Исключить из группы».
- Название группы уникально, 1–100 символов.

### 4.6. Доступ (US-17) — преподаватель

Раздел «Доступ»: выдача права сдавать лабораторные через включение студента в группу.

- Таблица студентов: `GET /api/v1/students?search=&groupId=&page=` — ФИО, логин, email, текущая группа; поиск по ФИО/логину/email, фильтр «без группы» (`groupId=none`), пагинация.
- Действие «включить в группу / перевести / исключить»: `PUT /api/v1/students/{id}/group {groupId: uuid | null}` — установка или сброс `group_id` пользователя.
- Следствия членства: студент без группы не отображается в ведомости (§4.4), его экран сдач показывает предупреждение; при включении в группу данные ведомости появляются.

### 4.7. Профиль (US-18) — все роли

- `GET /api/v1/me/profile` → `{login, email, fullName, role, groupName?}`; просмотр: ФИО, логин (только чтение), email, роль, группа студента.
- `PUT /api/v1/me/profile {fullName, email}` — редактирование ФИО и email (уникальность email; при конфликте — 409 с сообщением).
- `PUT /api/v1/me/password {currentPassword, password, confirmPassword}` — смена пароля из профиля: текущий пароль обязателен, новый — по требованиям §8; после смены прочие refresh-токены отзываются.
- Экран доступен в десктопной и мобильной вёрстках.

### 4.8. Оболочка и навигация (US-14)

- Вкладки в шапке: преподаватель — «Работы», «Сдача работ», «Группы», «Доступ», «Профиль»; студент — «Сдача работ», «Профиль».
- Неавторизованный: «Вход», «Регистрация», «Восстановление пароля».

### 4.9. Уведомления об ошибках (US-12)

- Единый компонент баннера: красный, с иконкой и крестиком, закрывается пользователем и по таймауту (5 с).
- Десктоп — всплывающий баннер поверх страницы (top-right); мобильный — inline-блок под формой.

### 4.10. Адаптивность (US-13)

- Breakpoint мобильной вёрстки: `< 768px`.
- Обязательные мобильные макеты: вход, регистрация, восстановление (оба шага), смена пароля, сдачи студента (US-11), профиль.
- Разделы преподавателя (работы, ведомость, группы, доступ) — desktop-first; на мобильных допускается горизонтальный скролл таблиц.

## 5. Модель данных (PostgreSQL)

```sql
CREATE TYPE user_role AS ENUM ('teacher', 'student');

CREATE TABLE groups (
    id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name       varchar(100) NOT NULL,
    created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (lower(name))
);

CREATE TABLE users (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    login         varchar(100) NOT NULL,
    email         varchar(254) NOT NULL,
    password_hash varchar(500) NOT NULL,          -- PBKDF2-SHA256, 210 000 итераций + соль
    full_name     varchar(200) NOT NULL,          -- ФИО
    role          user_role   NOT NULL DEFAULT 'student',
    group_id      uuid REFERENCES groups(id) ON DELETE SET NULL,  -- только для студентов
    created_at    timestamptz NOT NULL DEFAULT now(),
    UNIQUE (lower(login)),
    UNIQUE (lower(email))
);

CREATE TABLE labs (
    id             uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    semester       smallint    NOT NULL CHECK (semester BETWEEN 1 AND 10),  -- номер семестра курса
    number         integer     NOT NULL CHECK (number > 0),
    content        varchar(500) NOT NULL,
    assignment_url varchar(1000),                  -- null = ссылки нет
    defense_required boolean   NOT NULL DEFAULT false,
    created_at     timestamptz NOT NULL DEFAULT now(),
    updated_at     timestamptz NOT NULL DEFAULT now(),
    UNIQUE (semester, number)
);

CREATE TABLE submissions (
    id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    student_id   uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    lab_id       uuid NOT NULL REFERENCES labs(id)   ON DELETE CASCADE,
    submit_date  date,                               -- null = не сдано
    defense_date date,                               -- null = защита не назначена
    updated_by   uuid REFERENCES users(id),
    updated_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (student_id, lab_id)
);

CREATE TABLE refresh_tokens (
    id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id    uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash varchar(500) NOT NULL,
    expires_at timestamptz NOT NULL,
    revoked_at timestamptz,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE recovery_codes (
    id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id    uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    code_hash  varchar(500) NOT NULL,
    expires_at timestamptz NOT NULL,
    used_at    timestamptz,
    created_at timestamptz NOT NULL DEFAULT now()
);

CREATE INDEX idx_users_group        ON users(group_id);
CREATE INDEX idx_submissions_student ON submissions(student_id);
CREATE INDEX idx_submissions_lab     ON submissions(lab_id);
CREATE INDEX idx_labs_semester       ON labs(semester, number);
```

- Хранение дат — `date` (без времени), формат отображения `дд.мм.гггг` (как в макете).
- Верхняя граница семестра (10) — константа конфигурации `Labs__MaxSemester`, проверяется в CHECK (расширение — миграция) и в валидации.
- Начальные данные: миграция-сид создаёт одну учётную запись преподавателя из переменных окружения `Seed__TeacherLogin`, `Seed__TeacherPassword`. Студенты регистрируются самостоятельно (US-15).

## 6. REST API (`/api/v1`)

Базовый префикс `/api/v1`. Формат даты `YYYY-MM-DD`. Ошибки валидации — HTTP 400 с телом:

```json
{ "message": "Данные заполнены неверно", "errors": { "number": ["Номер должен быть положительным числом"] } }
```

| Метод и путь | Роль | Назначение |
|---|---|---|
| `POST /api/v1/auth/register` | — | Регистрация студента + автоматический вход |
| `POST /api/v1/auth/login` | — | Вход; ставит access/refresh cookie |
| `POST /api/v1/auth/refresh` | — | Обновление access-токена по refresh-cookie |
| `POST /api/v1/auth/logout` | user | Выход, отзыв refresh-токена |
| `GET /api/v1/auth/me` | user | `{login, fullName, role, groupName?}` |
| `POST /api/v1/auth/recovery/request` | — | Отправить код на email |
| `POST /api/v1/auth/recovery/confirm` | — | Проверить код → `resetToken` |
| `POST /api/v1/auth/reset-password` | — | Смена пароля по resetToken |
| `GET /api/v1/me/profile` | user | Данные профиля текущего пользователя |
| `PUT /api/v1/me/profile` | user | Изменить ФИО, email |
| `PUT /api/v1/me/password` | user | Смена пароля (текущий + новый) |
| `GET /api/v1/labs?semester=&page=` | teacher | Список лабораторных (пагинация, фильтр) |
| `POST /api/v1/labs` | teacher | Создать лабораторную |
| `PUT /api/v1/labs/{id}` | teacher | Изменить лабораторную |
| `DELETE /api/v1/labs/{id}` | teacher | Удалить лабораторную |
| `GET /api/v1/semesters` | user | Семестры, по которым есть лабораторные |
| `GET /api/v1/groups` | teacher | Список групп (+ количество студентов) |
| `POST /api/v1/groups` | teacher | Создать группу |
| `PUT /api/v1/groups/{id}` | teacher | Переименовать группу |
| `DELETE /api/v1/groups/{id}` | teacher | Удалить группу (студенты остаются, `group_id` сбрасывается) |
| `GET /api/v1/groups/{id}/students?page=` | teacher | Состав группы |
| `GET /api/v1/students?search=&groupId=&page=` | teacher | Список студентов (раздел «Доступ») |
| `PUT /api/v1/students/{id}/group` | teacher | Включить/перевести/исключить студента из группы |
| `GET /api/v1/submissions?groupId=&semester=&page=` | teacher | Ведомость группы: студенты × лабы |
| `PUT /api/v1/submissions` | teacher | Проставить/сбросить даты сдачи/защиты |
| `GET /api/v1/me/submissions?semester=` | student | Сдачи текущего студента по семестру (+`hasGroup`) |

Коды: 200/201/204 — успех; 400 — ошибка валидации; 401 — не авторизован; 403 — нет прав; 404 — не найдено; 409 — конфликт (дубликат логина/email, «семестр+номер» лабораторной, названия группы); 429 — превышен лимит попыток.

## 7. Маршруты SPA (Angular)

| Маршрут | Экран | Доступ |
|---|---|---|

- `authGuard` (неавторизованный → `/login`), `roleGuard` (чужая роль → 403-страница), `guestGuard` (авторизованный не видит `/login`, `/register`, `/recovery`).
- HTTP-интерцептор: 401 → попытка `POST /api/v1/auth/refresh`, при неудаче — редирект на `/login`; 403/400/429 → показ баннера с `message` из ответа. Базовый префикс `/api/v1` задаётся в одном месте (конфиг клиента).
- State: signals + сервисы поверх HttpClient; отдельный стейт-менеджер не требуется.

## 8. Валидации и тексты (соответствие макетам)

| Правило | Сообщение |
|---|---|
| Неверный логин или пароль (любая комбинация) | «Неверный логин или пароль» |
| Email не соответствует формату | «Введите корректный email» |
| Неверный/просроченный код восстановления | «Код восстановления не подходит» |
| Пароль: ≥ 8 символов, ≥ 1 цифра, ≥ 1 буква, ≥ 1 спецзнак; поля совпадают | «Данные заполнены неверно» + список ошибок у полей |
| Регистрация: занятый логин | «Пользователь с таким логином уже существует» |
| Регистрация/профиль: занятый email | «Пользователь с таким email уже существует» |
| Смена пароля из профиля: неверный текущий пароль | «Неверный текущий пароль» |
| Лабораторная: номер > 0, семестр 1…MaxSemester, содержание 1–500 символов, URL http/https | «Данные заполнены неверно» + подсветка полей |
| Дубликат (семестр, номер) лабораторной | 409, «Лабораторная с таким номером уже есть в семестре» |
| Группа: название 1–100 символов, уникально | «Группа с таким названием уже существует» |
| Студент не в группе (экран сдач) | «Вы не включены в группу, доступ к сдаче лабораторных не выдан» |

Валидация дублируется на клиенте (UX) и на сервере (истина).

## 9. Безопасность

- Пароли: PBKDF2-SHA256, 210 000 итераций, случайная соль (встроенный `Rfc2898DeriveBytes`), никаких обратимых хранилищ.
- Токены: httpOnly + Secure + SameSite=Strict cookie; refresh хранится хэшем и отзывается при logout/смене пароля.
- Восстановление: коды хранятся только хэшем, одноразовые, TTL и лимиты попыток (§4.2); ответы не раскрывают существование email.
- Rate limiting (ASP.NET Core built-in): login, register, recovery-request, recovery-confirm (§4.1–4.2).
- Регистрация создаёт только студента; повышение роли невозможно через API — смена роли отсутствует в v1 вовсе.
- CSRF: SameSite=Strict + отсутствие state-changing GET-эндпоинтов.
- XSS: Angular-санитизация; `assignment_url` на сервере проверяется на схему http/https.
- TLS terminates reverse-proxy; Kestrel — только внутренне.
- Все проверки прав — серверные (§3), клиентские guards не считаются защитой.

## 10. Нефункциональные требования и конфигурация

- Производительность: p95 API ≤ 500 мс на типовых запросах (объёмы: до 200 лабораторных, до сотен студентов и десятков групп).
- Локализация интерфейса — русская (тексты по макетам), date-picker `ru`.
- Логи: Serilog — запросы (метод, путь, статус, время), ошибки; PII и пароли не логируются.
- `GET /health` — 200 при живом соединении с БД.
- Конфигурация (окружение): `ConnectionStrings__Default`, `Auth__AccessTtlMinutes`, `Auth__RefreshTtlDays`, `Auth__JwtKey`, `Labs__MaxSemester` (по умолчанию 10), `Smtp__Host/Port/User/Pass/From`, `Seed__TeacherLogin/Password`, `Cors__AllowedOrigins` (только для dev-режима Angular dev-server).
